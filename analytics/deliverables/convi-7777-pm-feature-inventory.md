# CONVI-7777 — Assistance features for PM review

**Status:** Proposed v1 scope, October 9, 2026. Chat Smart Compose and all email use cases are P2; review of the remaining rules is pending. No metric has been implemented.

## What the new number would mean

For each Agent or Team row on Assistance Insights, report the percentage of **all filtered conversations** in which an agent used **at least one** feature below. A conversation counts once even if several features were used. A feature merely shown, sent, or generated does not qualify. The Agent and Team tabs use the same feature rules.

## Proposed qualifying features

| # | Feature | What counts as use in one conversation | Review state |
|---|---|---|---|
| 1 | Behavioral hints | A delivered hint with a linked positive adherence action. A correct behavior without a delivered hint does not count. | Proposed |
| 2 | Checklist hints | A delivered checklist hint with a linked positive adherence action. | Proposed |
| 3 | Knowledge Base hints | The agent uses a document chip from a delivered KB hint. Sending or viewing the hint alone does not count. | Proposed |
| 4 | Guided Workflow hints | The agent uses a workflow document chip from a delivered hint. | Proposed |
| 5 | GenAI answers | The existing detected “GenAI reply used” signal for the conversation. Showing an answer alone does not count. | Proposed |
| 6 | Summary | The proposed copy-only rule is an agent copying all or part of a valid generated summary. The current Summary RPC instead counts stored event types 1/2 (copy all or edit note) and misses type 3 (copy note). | **PM decision:** retain the current count rule for parity, or deliberately change the existing RPC to copy only before including Summary in the new metric. |
| 7 | Notes | The agent copies an automatically extracted entity, such as a name, phone number, or email address. Entity editing alone does not count. | **Copy only**, matching the current Notes analytics predicate and EA's consistency direction. |
| 8 | Knowledge Base search | A search issued in the conversation and a response returned. It may start from a typed query, suggestion, or chip; a search outside a linked conversation does not count. | Proposed; confirm whether all initiation paths qualify |
| 9 | Guided Workflow document use | The agent opens or navigates a workflow document in the conversation. Completion is not required. This can overlap a workflow hint; the recorded document event alone does not prove direct opening. | Proposed; confirm whether hint-originated opens qualify here too |
| 10 | Chat Suggestions | The agent uses a normal, hint-originated, or search-originated suggestion in the conversation. Sending/viewing a suggestion alone does not count. | Proposed |

Items 1–4 are hint uses; items 5–10 are other assistance. A feature may satisfy more than one item (for example, opening a workflow from a hint); the conversation still counts once. “Compliance” is not proposed as a separate category: a qualifying hint can follow the applicable hint rule above without double counting.

## Visible assistance features not currently proposed to qualify

| Feature | Proposed handling | Reason / decision needed |
|---|---|---|
| Reminder hints | Exclude | Delivery is tracked, but there is no comparable followed-use signal. |
| Chat Smart Compose | P2 | Out of v1 by scope decision. The current statistic cannot assign use to a conversation, but newer stored use events do have conversation IDs. A P2 query would need coverage and filter validation. |
| Silence/Hold hints | V1 candidate gated by `enableSilenceHoldHintsTab`; qualifying-use signal pending | The flag currently gates the dedicated Assistance Insights tab, which is also hidden after loading when its calculated sent count is zero. The displayed “followed” number derives from behavior adherence and policy configuration, not proof that a hint was delivered for each occurrence. Resolve whether the new metric requires a delivered-hint/positive-action link before counting. [Tab gate](https://github.com/cresta/director/blob/da2e210926b60faefcdef8ede940ff40575d0e50/packages/director-app/src/components/insights/assistance/assistance-insights-statistics/assistance-insights-carousel-menu/AssistanceInsightsCarouselMenu.tsx#L484-L488), [stats adapter](https://github.com/cresta/director/blob/da2e210926b60faefcdef8ede940ff40575d0e50/packages/director-app/src/components/insights/hooks/useGetSilenceHoldHintStats.tsx#L29-L39) |
| Customer Snapshot | Exclude from v1 | Previously scoped out. The current API measures panel presentation/duration, not a clear active-use action. |
| Email partial/full reply Suggestions | P2 per EA | Used events have conversation IDs and the current Suggestions API counts them. Product prioritization, not linkage, keeps them out of v1. |
| Email Smart Compose | P2 per EA | A conversation event exists, but current assistance stats do not count it. Including it needs a new query/projection and a retained-text decision. |
| Email inserted search result | P2 per EA | A conversation event exists, but current assistance stats do not count it; insertion does not prove the content stayed in the reply. |
| Viewed email Suggestions; generated summaries; sent-only hints; shown GenAI answers | Exclude | Exposure or generation alone is not active use. |

External URL hint clicks, GenAI rationale clicks, workflow automation, kudos/reinforcement, and other event types are not in the current page-level usage inventory. They should be scoped explicitly if PM wants them included rather than inferred from event existence.

## Decisions requested from PM

1. Approve or edit the proposed feature list and the common rule: **at least one qualifying use per conversation**.
2. Notes direction from EA: stay consistent with the current analytics number, so count CopyEntity only. Validate the new query independently of the existing Notes metadata-filter branch.
3. Resolve Summary's current SQL predicate (copy all or edit note) versus the proposed copy-only wording. Existing SQL/code is the source of truth for the current count; changing it requires a deliberate existing-RPC decision.
4. Confirm with EA that chat Smart Compose is P2 and excluded from v1, like all email assistance. The current stats implementation cannot attribute use to a conversation, although newer stored events can; P2 still needs coverage and use-predicate validation.
5. Gate Silence/Hold in the new metric on the profile's `enableSilenceHoldHintsTab` setting. The flag currently gates its Assistance Insights tab; it does not prove occurrence-level hint delivery. The qualifying-use signal remains to be settled before this category can count.
6. EA prefers all email use cases in P2. Email partial/full Suggestions can be tied to conversations and are already counted by SuggestionStats; email Smart Compose/search have conversation event contracts but need new stats query/projection work. Exclude all three from the v1 union.
7. Confirm whether any in-conversation KB search qualifies, including searches started from suggestions or chips, and whether workflow use from hints and step navigation qualifies alongside direct opening.

## Evidence and implementation caveat

This list is grounded in the current Assistance Insights tabs, Director's split stats adapter, analytics queries, and conversation event contracts. [Detailed source audit](convi-7777-conversation-assistance-usage-draft.md) records the exact paths and caveats. Source inspection does **not** establish customer-specific event coverage or historical completeness. The new number must be computed from distinct qualifying conversations; adding the existing per-feature counts would double count.
