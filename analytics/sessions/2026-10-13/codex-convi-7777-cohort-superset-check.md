# CONVI-7777 cohort superset check

**Date:** 2026-10-13  
**Primary source repo:** `/Users/xuanyu.wang/repos/go-servers`  
**Source context:** `/Users/xuanyu.wang/repos/go-servers-convi-7777-assistance-usage`, branch `xw/convi-7777-assistance-usage`; related Director worktree `/Users/xuanyu.wang/repos/director-convi-7777-assistance-usage`, same branch. Source review only; no customer data queried.

## Question

Does the current Assistance Insights `RetrieveConversationStats` population approximately contain the conversations represented by all V1 feature APIs? Split eligibility into filter parsing and SQL population restrictions. Value-or-missing parsing is deferred by user direction.

## Findings

1. **Time field aligns for this page.** The Assistance chart calls `useInsightsRequestParams` with `defaultOptions` containing only `filterToAgentsOnly`; the Assistance Used leaderboard passes `filterOptions` that likewise contains only `filterToAgentsOnly`. `useInsightsRequestParams` forwards `filterOptions?.conversationTimeRangeField`, so this page leaves it undefined. `RetrieveConversationStats` resolves unspecified to `conversation_start_time`; only explicit `CONVERSATION_ENDED_AT` selects end time. The V1 feature queries default to conversation start time. See Director `AssistanceInsightsContainer.tsx:88-112,141`, `AssistanceInsightsStatistics.tsx:107`, `AssistanceUsedLeaderboardContainer.tsx:41-53,90-94`, `useInsightsRequestParams.ts:42-54`; backend `common_clickhouse.go:2044-2063`, `retrieve_conversation_stats_clickhouse.go:581-584`.
2. **Source 7 is server-controlled.** The page does not send a bot-source override for these requests. `RetrieveConversationStats` calls `IncludeConversationSourceBot`, which reads the profile's `disable_stats_for_conversation_source_bot` setting; its SQL uses source `(0,8)` or `(0,7,8)`. `RetrieveHintStats` uses the same setting, plus an `IncludeCrestaBot` request option; this page's request attributes do not set that option. `RetrieveKnowledgeAssistStats` fixes source `(0,8)` even when the profile permits 7. See backend `retrieve_conversation_stats.go:138-145`, `shared/common.go:1227-1237`, `retrieve_conversation_stats_clickhouse.go:602-608`, `retrieve_hint_stats_clickhouse.go:410-416`, `retrieve_knowledge_assist_stats_clickhouse.go:159-163`.
3. **Nonempty agent largely aligns, but row roots do not.** All audited V1 queries require a nonempty agent on their queried feature rows. `RetrieveConversationStats` additionally requires matching `(conversation_id, agent_user_id)` rows in both `conversation_d` and `message_d`, source eligibility, and `is_dev_user=0`. Summary, Notes, KB search, Guided Workflow, and Suggestions do not impose source or dev-user restrictions in their SQL. KB search and Suggestions root at event rows; Summary roots at `conversation_d`; Notes and Guided Workflow join conversation and event rows by conversation ID, which need not match agent IDs. HintStats allows NULL `conversation_source` on feature rows. GenAI uses agent/time grouping rather than a conversation-key join. See the V1 semantics audit's per-API table.
4. **Shared parsing does not imply identical filter effects.** User resolution is shared, but `parseClickhouseFilter` lowers filters against different target tables. Behavior/policy/moment, use-case/duration, and metadata filters can be unsupported or interpreted differently by a given table; Notes and Guided Workflow change physical clusters under metadata filtering. This is separate from value-or-missing parsing. The frontend sends the same user/date/filter values to the Assistance requests, but this does not establish equal selected rows.

## Conclusion

`RetrieveConversationStats` is a reasonable compatibility **denominator** for the new page metric and includes conversations without assistance. It is **not a provable superset** of the current feature APIs, even with aligned start-time filtering. Source-level counterexamples include a non-dev HintStats record with NULL source, or a qualifying Suggestion/KB event on a conversation without a matching eligible message row; source types outside 0/8 and dev users can also be counted by several feature APIs. Whether these exceptions are rare enough to call the denominator an *approximate* superset requires customer-row anti-join counts. No such data was queried. The new API should continue joining feature evidence to the denominator cohort so its numerator is a strict subset by construction; a separate follow-up could measure and decide whether to align existing feature RPC populations.
