Per-conversation usage reasons are still missing

CONVI-7777 · Verified October 22, 2026 · Source audit, no product changes.

Protobuf: defined · Backend: explicitly unsupported · Frontend: aggregate percentages only

What the API promises

With include_conversation_usage_details=true, return every eligible conversation, its eligible agents and each agent’s distinct qualifying feature categories. Include no-use records so the numerator and denominator can be checked. “Reason” means a feature category such as Notes or KB search; raw events and transcripts are not part of this contract.

Normal requests remain aggregate-only. The initial design was for diagnostics; a customer-facing conversation drawer is a separate product decision.

Actual flow

Details requested → validation → Unimplemented (before database reads)
Normal request → eligible population → seven evidence queries
               → union of conversation/agent pairs → counts
               → Director group percentage → Agent/Team column

The evidence union retains whether use happened, but loses which feature caused it. The general header tooltip does not explain an individual conversation.

What needs completing
  1. Preserve deduplicated feature categories per eligible conversation/agent, including all four hint categories, using the same evidence as counts.
  2. Build complete opt-in details, including zero-use records; retain authorization and disabled details logging. Define explicit failure behavior when complete details cannot be returned.
  3. Replace the rejection test with count-reconciliation, duplicate, multi-feature, multi-agent, grouping-independence and completeness cases.
  4. Expose the opt-in and preserve details in Director’s adapter if diagnostics should use it. Decide separately whether a UI reason view is wanted.
Recommendation: Do not describe the reasons feature as implemented. It was explicitly deferred from the counts work; no defect in the aggregate metric is demonstrated by this audit. Non-blocking maintainability: no separate issue identified.
