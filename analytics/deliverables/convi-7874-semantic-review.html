Purpose and expected behavior

A non-admin at Sunbit has Conversation Access Control enabled and Advanced Data Access Control disabled. The author reports zero conversations when filtering by Group, while an admin sees about 1.7K. That customer count is from the PR description, not a live reproduction in this review.

Input

Selected users, Teams and dynamic Groups, with optional exclusion of deactivated users. The frontend can send dynamic Groups either in groups or separately in dynamic_groups.

Expected result

Resolve the selected audience, apply activity restrictions, then intersect with the caller’s allowed users. A dynamic Group grants no extra access.

Must avoid

False empty results, dropping selected filters, adding inactive users after they were excluded, or treating an empty selected group as an unfiltered request.

Terminology: a Team is part of the managed authorization hierarchy. A dynamic Group is a user selection whose members must pass user-level access checks. ACL means access control list.

Production workflow

Director selections→groups / dynamic_groups→Pre-expand split-field members→Read caller ACL→Resolve types and retain Groups→Expand Teams / apply active filter→Late split-field merge→Final ACL user intersection→Elasticsearch query

The existing PI path remains RetrieveQAScoreStats → ParseUserFilterForAnalytics. Closed Conversations instead calls ApplyResourceACLToAttributeFilter. Only the metadata lookup is shared by this PR; the full audience logic is still separate.

The order highlighted here explains both findings: selected members arrive after earlier filtering decisions. There are no writes, migrations or frontend changes in this PR.

P2 · introduced regression
1. Apply deactivated-user filtering after merging dynamic members
common.go:1293–1294 appends raw dynamicGroupMemberUsers after MoveFiltersToUserFilter has already enforced ExcludeDeactivatedUsers. For root callers this is a newly reachable merge; it can add inactive users back into the query.
Concrete input: root/admin caller; explicitly selected active user A; selected dynamic Group G contains inactive user B; exclude_deactivated_users=true; both have conversations in the time range.
  1. The caller pre-expands G and supplies A/B. The helper derives B as the supplemental dynamic member.
  2. MoveFiltersToUserFilter intersects explicit A with active users and leaves A.
  3. The new merge appends B without applying the active restriction again.
  4. The root caller skips the final ACL intersection. Final query users are A/B instead of A.
Before → after: the same compiled fixture passes against base with A, and fails against head with A/B.
Reachability: the normal Director conversation filter supports explicit users, dynamic Groups and the deactivated-user toggle together. ListUsersFromDynamicGroups sets no active-state filter; UserService’s default includes active and inactive users. This is incorrect filtering for an authorized admin; no cross-ACL disclosure is established.
Related incomplete behavior: with no explicit user, Group {A,B}, active universe {A,C}, the active-only move selects all active users before the late merge. Head yields A/B/C rather than A. The extra active C already appears at base; adding inactive B is the new regression.
Fix sketch: merge every selected member audience before calling MoveFiltersToUserFilter, then apply activity filtering and ACL narrowing once. Avoid re-appending the original unfiltered member list afterward.
Regression: root + explicit active A + inactive dynamic member B + exclude inactive → A only. Also test dynamic-only {A,B} with unrelated active C → A only.


P2 · incomplete split-field handling
2. Combine split-field Groups before deciding the audience is empty
common.go:1285–1286 returns empty when the groups expansion is empty, before the new dynamic_groups merge. The team-only denial at 1239–1240 has the same problem: its dynamicGroups variable only covers dynamic entries in groups.
Normal root example: select empty Team T together with dynamic Group G containing active A; Director’s split flag sends groups=[T], dynamic_groups=[G].
  1. The caller successfully pre-expands G to A.
  2. Root bypasses team ACL narrowing.
  3. MoveFiltersToUserFilter expands the empty Team to no users.
  4. hadGroupFilter=true, so line 1285 returns empty before A is merged.
Observed: empty response, expected A.
Second reproduction: for a scoped caller, an inaccessible Team in groups plus an accessible dynamic Group in dynamic_groups returns empty at 1239. Sending the same Team and Group together in legacy groups succeeds at this head. The inaccessible-Team example may require a stale selection after a role change or a direct caller; the empty-Team root example does not.
Classification: these split-field combinations were also broken before the PR. This is an incomplete part of the newly added split-field/root and mixed-selection support, not a newly introduced outage. It contradicts the promise that an empty Team must not cancel another valid selected audience.
Fix sketch: evaluate emptiness over the complete union of explicit users and resolved Team/Group members. Check all split-field selections before returning empty, then narrow the union through activity and access checks.
Regression: root + empty Team + dynamic Group A → A; scoped caller + inaccessible Team + allowed dynamic Group A → A, with equal results for legacy and split request formats.


Effects beyond the changed lines
  • Other callers: conversation-message retrieval and message statistics both pass the old optional empty-result setting as false. Tracking a selected group now prevents the whole-ACL fallback for these callers.
  • Charts: the chart ACL wrapper also uses this helper with users/groups; extra type lookups therefore affect its selected Team path. Updated mocks are included in the PR.
  • PI compatibility: #33026 normalization remains; its private resolver is extracted into the shared package. Authoritative name/type/customer checks are retained.
  • Upstream contract: Director’s existing split flag changes where Group IDs are sent. The conversation hook actually passes the option into the shared request builder.
  • Configuration: split-field pre-expansion still depends on ENABLE_DYNAMIC_GROUPS_ACL. The PR says it is enabled in all current releases; that deployment-wide statement was not independently audited here.
  • Failure paths: metadata errors from the new type lookup propagate. The older split-field pre-expansion helper still logs list errors and returns any accumulated members; that pre-existing error contract was not changed in this review.
  • Persistent data: none is modified. Member and ACL reads determine the query audience; deployment behavior and customer membership freshness remain unverified.
