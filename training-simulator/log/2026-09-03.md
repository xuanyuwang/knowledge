## CONVI-7601 configured-zero quiz passing score fix (Claude Code)

Review-driven fix on top of the quiz-stats commit.

- Decision: a configured `EvaluationConfig.passing_score` of `0` is a valid threshold (formula `score >= passing_score/100` ⇒ every scored attempt passes). `quizScoreToLatestResult` had gated on `passingScore > 0`, treating configured-0 the same as missing.
- Distinguisher evidence: `passing_score` is `double` with no proto3 `optional` (advisory `field_behavior = OPTIONAL` only), so `GetPassingScore()` is `0` for both unset and explicit-0. Plumbed `hasPassingScore = EvaluationConfig.Message != nil` (the only available "configured" signal; cross-checked against `fetchModulePassingScores` and `ConvertQuizScoreDBToTaskRunAPI`'s `*float64` presence pattern).
- Behavior: configured >0 unchanged; configured 0 → every scored attempt passes; no EvaluationConfig → pass undefined; `normalizedScore` untouched.
- Test: `TestRetrieveTrainingSimulatorModuleStats_QuizPassingScoreZero` (threshold 0, two scored attempts → both pass, avg 0.25). Suite PASS (8.7s).
- Deliberately did NOT change `fetchModulePassingScores`'s `ps == 0 → skip` (it backs the quiz-run creation gate; out of scope for a stats-reader fix).
