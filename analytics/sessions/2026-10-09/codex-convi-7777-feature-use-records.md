**Question:** Does every proposed feature have a stored record that could substantiate at least one qualifying use in a conversation?

**Result:** [The PM inventory](../../deliverables/convi-7777-pm-feature-inventory.md) now has a row-by-row evidence table. Behavioral/checklist hint use is positive adherence in `moment_annotation_d` tied to a delivered action; KB/GW hint use is a `USED_HINT_DOCUMENT_CHIP` event tied to the relevant action type; GenAI answer use is a `KA_GEN_AI_REPLY_USED` moment; Summary use requires a copy event plus valid-summary action in the same conversation/agent; Notes, KB search, workflow document use, chat/email Suggestions, and Smart Compose all have conversation event contracts. The analytics queries read corresponding signals for items 1–12, subject to the Notes/GW metadata enum defects and the Summary copy/edit predicate mismatch. Smart Compose is different: its current stats query infers use via agent/hour from legacy events, so it cannot directly supply conversation membership, even though newer conversation events exist.

**Wording corrections:** `USED_KB_SEARCH` means a search was issued and a response returned; it can start from typing, a suggestion, or a chip. `USED_KB_DOCUMENT` can be created by direct opening, hint-chip opening, or workflow step navigation. These events cannot prove the original inventory's narrower “explicit” search or “opened directly” distinctions on their own. The proposed list now describes the recorded actions and calls out PM scope decisions.

**Summary source mismatch:** `RetrieveSummarizationStats` uses `summarization_payload_data_type IN (1,2)` and calls both copy. In the persisted PostgreSQL event oneof and `buildConversationEventRows` mapping, 1 is copy all, 2 is edit a note, and 3 is copy one note. Thus the current query can count edit-only conversations and miss copy-one-note conversations under the proposed copy-only rule. The new metric should use 1/3 in the conversations cluster. This is source-level; live impact remains unmeasured. Corrected the prior [API semantics audit](../../deliverables/convi-7777-assistance-api-semantics-audit.md).

**Limits:** This is source-level record and predicate verification, not proof of deployed coverage, actual customer rows, complete historical data, or producer reliability. Hint action existence and transfer-agent attribution need validation in the new denominator-rooted query. Summary's current query joins a valid summary and a selected event by conversation/start/agent, not by specific annotation. Smart Compose's retained-text criterion is unresolved and the conversations-cluster projection omits `used_text_length`. No production data, tests, product code, Linear, or credentials were used.
