Preserved correctness issues and quirks

Default LEFT JOIN exclusion drops nonmatching rows

Trigger: An eligible conversation has no excluded metadata row and join_use_nulls=0.

Observed: The joined String key defaults to empty string; IS NULL is false, so the row is dropped. The same fixture qualifies with join_use_nulls=1.

Boundary: Preexisting metadata exclusion behavior. A correction belongs in shared metadata filter construction with a dedicated before-fix regression case.

Feature eligibility differs from conversation population

Trigger: An event belongs to source 9 or a developer user.

Observed: Legacy feature statistics retain it. Tests pin this behavior to avoid changing scope during extraction.

Boundary: Future Assistance Usage API must choose its population contract separately.

Effects beyond the diff

Existing callers: continue through the same reader, connection selection, user tables, and response conversion. Selection moves behind feature-specific helpers; aggregation remains with the old RPC.

Data and authorization: no writes or schema migration. Request resolution and ACL logic remain outside the extraction boundary. Existing source/metadata quirks are characterized rather than silently corrected.

Future callers: may consume shared evidence rows after a separate review of cohort eligibility and use semantics. This stack does not wire the new API or establish that legacy aggregate denominators are appropriate for that API.

Cost: SQL shape may add named relations. No production query-plan, transferred-key, p95 latency, memory, or concurrency benchmark is claimed.
