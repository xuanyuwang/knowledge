## Current Understanding

The primary confirmed root cause is an online-event interval-selection regression in `cron/sync-users/internal/conversation-agent-assistance/task.go`. The June 10 per-message labeling change replaced the original interval-overlap predicate (`session.start <= window.end AND session.end >= window.start`) with a predicate that only accepts sessions whose **start time** falls inside the batch window. The caller expands the batch by only three hours. Long Agent Assist sessions that begin more than three hours before the batch, but still overlap the agent's calls/messages, are omitted. Their messages therefore produce no `conversation_with_labels_d` rows and `RetrieveAgentStats` returns Active Days `0` for days that have conversations, or the UI can display `N/A` when the agent/day result row is absent.

Production evidence directly reproduces this for Janalie Shene Labeste and Kyle Batobato. A second pattern applies to Mervel Molina: the observed heartbeat rows use application type `DIRECTOR` (5), which is intentionally not one of the Agent Assist application types `(0, 2, 4, 8)`. A green Director presence indicator is therefore not sufficient evidence for Active Days.

The ticket's earlier transfer/stale-label hypothesis is not supported by current data for conversation `0MwVq00000Wz7rl`: both `conversation_d FINAL` and `conversation_with_labels_d FINAL` currently identify Adrian Vergara (`357c34531b4e15f5`) with use case `b2b-chat-care`. That historical state may have changed, but the current rows do not prove a stale assignment.

- Bill West resolves to app DB `bill-west-us-west-2`, conversations DB `bill_west_us_west_2`, and auth-events DB `auth_bill_west` on `us-west-2-prod`.

The session began about 5h50m before the first call, outside the three-hour start-time buffer.
- Janalie repeats the fingerprint on the 2026-08-13 Manila day: 8 conversations and 41 messages (`20:40:21Z`–`22:21:01Z`) overlap a session starting `16:44:06Z`; Active Days labels remain zero (one non-active fallback row exists).
- Kyle on the 2026-07-23 Manila day had 7 conversations and 82 agent messages (`16:25:42Z`–`21:42:19Z`) inside an application-type-0 session from `12:54:13Z` through `22:03:00Z`, but has zero label rows for the day. The session began about 3h31m before the first message.
- Kurt Moscardon and Janine Garcia have positive labels on the inspected 2026-07-23 and 2026-08-11 dates; the investigation does not support a blanket Bill-wide absence.
- Mervel's inspected July heartbeat events are application type 5 (`DIRECTOR`), which the labeling job excludes by design; this supports an adoption/application-state explanation for that subset rather than the interval-query bug.
- The June 10 commit `7950abdd8e` changed the ClickHouse event predicate from true overlap to bounded session starts. Current `origin/main` still contains the regressed predicate.
- The remembered three-hour fix is go-servers PR [#29058](https://github.com/cresta/go-servers/pull/29058), merged June 18. It removed the batch-time predicate from `findAgentMessages` so messages from multi-day conversations are loaded. It did not change `findOverlappedAgentOnlineEventsFromCH`; the session-start-only ±3-hour predicate remains on current `origin/main`. PR [#31299](https://github.com/cresta/go-servers/pull/31299) separately added a lookback for late-ingested conversations and also leaves this predicate unchanged.
- Open go-servers PR [#32443](https://github.com/cresta/go-servers/pull/32443) at `c3a99f49670d093767bb89861ed955b0efcf6d9c` makes the exact required predicate change to `endTime >= batchStart AND startTime <= batchEnd`. It directly covers the confirmed Janalie and Kyle long-session fingerprints. Required cron-sync-users Bazel CI passed; code-owner and `donotmerge` contexts remain pending.
- No Director UI inspection was needed: the decisive evidence is historical and persisted at label-generation time, whereas the open UI reflects current filters/state.
