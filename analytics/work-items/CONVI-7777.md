## Findings and Decisions
- Revised API approved: `RetrieveConversationAssistanceUsageStats`, sharing internal ConversationStats eligibility and small feature-use query functions. Protobuf [PR #10283](https://github.com/cresta/cresta-proto/pull/10283) is merged; backend/frontend implementation follows the scoped stack.
- Settled aggregation: distinct conversations per agent, Team sums of agent counts (including shared conversations and overlapping Team membership), and distinct conversation IDs for ungrouped overall results. Use is credited only through the eligible agent who used assistance. Conversation start time defines both eligibility interval and trend buckets.
- Use assistance terminology/scope, not just hints; conversation adoption, not pooled feature usage rate.
- Confirmed denominator: all filtered conversations, including no assistance offered.
- Confirmed placement: both Agent and Team tabs.
- Alignment decision: use the existing SQL and code as the source of truth for each feature's current count/use predicate. Align the eligible conversation population and attribution for the new union percentage; do not redefine current feature counts as part of that API. Where a current predicate conflicts with proposed product wording, resolve the discrepancy explicitly.
- Inventory/usage definitions accepted in principle. EA asked that Notes match the current Assistance Insights number; current `RetrieveNoteTakingStats` counts CopyEntity only, so the proposed rule is copy-only despite the broader Notes card tooltip. Chat Smart Compose is P2 and out of v1, like email assistance. The current stats API cannot assign its legacy use events to conversations, but newer stored `USED_SMART_COMPOSE` events include conversation ID and payload, so technical inclusion remains possible in P2 with a new query. Historical coverage and filter parity remain unverified.
- Sent-only hints do not count. Silence/Hold is a conditional v1 candidate guarded by the profile's `enableSilenceHoldHintsTab` flag. It has tracked behavior adherence, unlike Reminder, but the flag does not prove hint delivery and its qualifying-use signal remains open.
- Customer Snapshot excluded from v1. EA prefers all email use cases in P2, including partial/full Suggestions. Those Suggestions are conversation-linked and covered by `RetrieveSuggestionStats` and Director's split adapter. Email Smart Compose and inserted search result events also have conversation linkage, but no current stats query; including them later requires new projection/query work and a chosen use predicate. Historical coverage not verified.
- Current Silence/Hold page counts derive from adherence moments and policy-level hint configuration, without per-occurrence delivery proof. Do not use those aggregates as qualifying conversations.
- Director has a dedicated Silence/Hold hints tab, shown only when `enableSilenceHoldHintsTab` is on and calculated sent volume is nonzero after loading. Absence in one staging view does not establish the feature is absent from Assistance Insights; the exact staging profile/flag/data state was not inspected. Inclusion in the new metric remains on hold for a per-occurrence delivery/positive-action link.
- Source-level evidence maps the 10 proposed v1 categories, two P2 email Suggestions, and P2 chat Smart Compose to their feature-specific use records in the [PM inventory](../deliverables/convi-7777-pm-feature-inventory.md). The proposed items have a record/predicate path in principle, but Summary's existing RPC treats stored edit type 2 as copy and misses single-note copy type 3. Chat Smart Compose has a conversation event but its current stats API relies on agent/hour and the conversations-cluster projection loses retained length. `USED_KB_SEARCH` includes typed, suggestion, and chip origins; `USED_KB_DOCUMENT` can include hint-originated opens and workflow step navigation. These origins need PM wording decisions if categories should be mutually distinct. No customer-row coverage check was performed.

  value: enableAssistanceUsageMetric,
  isResolved,

  isResolved && enableAssistanceUsageMetric;
