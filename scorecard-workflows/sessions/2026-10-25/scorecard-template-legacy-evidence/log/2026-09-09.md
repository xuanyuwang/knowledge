# 2026-09-09

- Investigated the oversized `ListCurrentScorecardTemplates` production failure for RCG.
- Confirmed the permission hook requests the default full view across all usecases while consuming only template identity and permissions.
- Measured 3,330 selected current rows and about 69 MiB of stored template/config/permission JSON through the read-only app-DB workflow; no single oversized row exists.
- Identified a permissions-only view plus Director migration as the bounded primary fix; pagination remains a broader full-list contract improvement, while raising the gRPC limit is only a temporary mitigation.
- Merged the related scorecard-export alert into the same oversized-response investigation. Groundcover confirmed it is a separate `cresta-sandbox-2 / voice-sandbox-2` incident: a 250-comment page exceeded the apiserver client's 4 MiB receive limit. The common design failure is record-count paging that does not bound serialized bytes; adaptive comment paging is separate from the template permissions-only fix.
- Created [CONVI-7663](https://linear.app/cresta/issue/CONVI-7663/bound-coaching-list-responses-by-serialized-size) with the agreed priority order and opened a background audit of `EvaluateScorecardsPermissions` and Director permission consumers.
- Completed the permission audit: `EvaluateScorecardsPermissions` requires persisted scorecards and only implements submitted-lock modification (with deny-only `VIEW`), so it cannot replace the five-decision template hook. Added the preferred batched template-permission API and lower-cost permissions-only view tradeoff to the ticket and investigation.
