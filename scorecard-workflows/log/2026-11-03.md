- Explained the supplied scorecard total/row inconsistency against current go-servers source. Reading and recalculating inside a transaction fixes a stale request only when the read includes the other update; it still races if another updater commits after that read. A parent lock before reading score rows, shared by all relevant writers, can serialize the calculation and writes under READ COMMITTED. No implementation or live database verification.
