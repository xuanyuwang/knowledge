How an override preview grows into a safe evaluation path

This PR computes an on-demand grade preview for an existing Training Simulator attempt after a manager proposes criterion overrides. The preview is returned without saving it.

Read-only reviewPart 2 of 3Base 24706da3f3Head 68f22ba24f

Your interpretation: yes, with one qualification

The handler loads the named run's saved criterion results and historical module rules, applies only the proposed verdict changes, then recalculates score and pass/fail for the response. That is an on-the-fly preview of how this saved attempt's grade would look with the overrides.

Saved attempt+Proposed verdicts→Recalculated preview

It does not rerun the AI model or modify the run. It does re-evaluate stored moment annotations to check that the saved AI result was complete; those annotations do not replace the saved verdicts being previewed. The separate module-preview mode cannot be combined with criterion overrides. See the override path.

05 / Outside the diff
Three side-effect paths worth tracing

        

          
Normal AI evaluation
The new shared scorer also replaces the old normal-path calculation. A bounded 43,275-case comparison over N/A, pass, weights, auto-fail, and thresholds matched the old algorithm; this is analytical evidence, not a runtime test.

          
Annotation lifecycle
The completion check depends on the annotations stored now. The direct DB read fixes retired-policy filtering, while the saved pending/N/A encoding still limits what can be proven about the original save.

          
Save handoff
Part 1 protects a committed manual override from delayed automatic writes. Part 2 previews. Part 3 must verify and commit under its own locking rules; preview alone provides no reservation.

07 / Review outcome
What this case teaches the skill

        

          
Merge recommendation
Near ready from a code review standpoint. I found no merge-blocking correctness defect in the production path at the pinned head. It validates identity and access, uses historical rules, checks for unfinished saved results, merges sparse verdicts, and recomputes the grade without writing. The required CI check and affected apiserver checks pass. As checked on 2026-10-06, GitHub still requires codeowner approval before merge.
The code comment at the override entry says no annotations are fetched, but the final path reads stored annotations for completion. Update that comment for accuracy; it is a review-clarity fix, not a demonstrated runtime blocker. The saved pending/N/A ambiguity remains a data-model limit, with no incorrect final grade established by this source review.

          
Alternative to compare
A durable completion marker would make the original state explicit and remove the need to infer it from current annotations. It requires a data-contract and migration decision beyond this PR. The review should state that tradeoff, not declare a universal best approach.
