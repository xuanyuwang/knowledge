## Core implications for the draft

1. The template/criterion JSON model can remain authoritative. It does not need a criterion table merely to support these page filters. The largest additional schema choices are **QM task scope** and **coaching-plan scope**, both currently singular.
2. The reusable boundary is a normalized function that answers which use cases a template, criterion, QM task, or coaching plan applies to, then intersects it with the page-selected and entitled use cases. The task and plan scopes need their own model decisions; they are not interchangeable with criterion scope.
3. A universal template query layer is insufficient: QM stats, coaching overviews/progress, and coaching efficiency read relational tables or template JSON directly. The migration inventory should name each read path.
4. PostgreSQL `EXPLAIN` comparisons should follow the task/plan representation and query rewrite. Running them on today's singular-scope queries would benchmark a query that cannot deliver the PRD behavior. Use representative shared-template, multi-plan, and filtered-use-case fixtures; measure result cardinality and latency as well as the plan.
5. Historical scorecards remain included according to their pinned template revision when reporting across a later scope change, as confirmed by Xuanyu on 2026-10-08. Do not filter historical rows against only the latest criterion scope.
