What both fixes promise

A dynamic Group is a selection of users; a Team is also part of the authorization hierarchy. Resolve their types from UserService, expand the selected dynamic members, and restrict the result to the caller’s allowed users. Neither PR changes filter tabs.

PI: RetrieveQAScoreStats → ParseUserFilterForAnalytics → authorized user audience

Conversations: RetrieveClosedConversations → ApplyResourceACLToAttributeFilter → member expansion → authorized user audience → Elasticsearch

The two callers use separate filtering implementations. Sharing a UI filter does not make them share a backend parser.

How the fixes relate

These are explanatory code snapshots, not compilable excerpts or a claimed commit sequence.

What the new PR adds
  • Applies the earlier idea to the conversation helper, including the Conversation Access Control on / Advanced Data Access Control off configuration.
  • Preserves the separate Attribute.dynamic_groups filter for root/admin callers.
  • Stops empty selected groups from falling back to every allowed user, including the two message RPCs with the optional empty-result check disabled.
  • Keeps a dynamic group selected alongside an inaccessible team.
  • Moves our old private resolver into shared.SplitGroupsByType; PI keeps its existing behavior.

Effects and limits
The conversation helper is also called by message retrieval, message statistics, and chart ACL filtering. The type resolver is shared; the full audience parsers remain separate. No writes, migration, frontend edits, or changes to the team-only ACL universe appear in this PR.
The pre-expansion of the separate dynamic_groups field still depends on ENABLE_DYNAMIC_GROUPS_ACL. No deployment/configuration audit, Go tests, or live customer requests were run here. New regression tests were inspected.
Findings and maintainability
No additional defect is asserted by this comparison. This was not a full security or merge review. Sharing the lookup reduces duplication, but it does not unify the two filtering pipelines.
Recommendation
The new PR addresses a path the earlier fix did not cover. It is not redundant. Complete staging validation for the Sunbit configuration before drawing a deployment conclusion.
